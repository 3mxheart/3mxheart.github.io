把 REA 的中文官网在本地跑起来，并 fork 了一份

2026-10-14

REA 是一个"逆向一切"的 MCP 服务：把智能体接到 Hopper、Ghidra、IDA、JADX 这些分析工具上， 在本机逆向二进制、Electron 应用、.NET 程序集、网站等等。我在 rea-cn 这个仓库里保存它的中文官网源码。

仓库里有什么

它不是 REA 本体，只是一套静态官网：Astro 负责生成页面，React 处理几个交互组件， 样式用 Tailwind。站点一共三个页面——首页、使用指南、案例，文案都是中文， 但"打开指南""看案例"那些链接仍然跳回英文站。

把它跑起来

仓库里的依赖没有随代码一起打包，所以第一步是装依赖。这台机器上没有正经安装的 Node， 只有 HBuilderX 自带的一份，于是用它带上 npm 来装： 

$n   = "...\HBuilderX\plugins\node\node.exe"
$npm = "...\HBuilderX\plugins\node18\npm\node_modules\npm\bin\npm-cli.js"

& $n $npm install
& $n $npm run build     # 产出 dist/，三个页面
& $n $npm run dev        # 开发服务器，附带热更新

装依赖花了五分钟，构建只用了一秒不到。构建产物是静态 HTML，随便找个能起静态服务的工具 指到 dist 目录就能看效果。

接上自己的账号

下载下来的 zip 解压之后是没有 .git 的，也就是说它暂时没法提交、也没法推送。 于是补上：初始化仓库、把 origin 指向自己的 fork、拉取远端分支， 再把本地的工作目录对接到 origin/main。这样一来，本地既能保留已经装好的 node_modules，又能正常提交和推送。

值得记下来的两点

  • git init 之后执行 git reset origin/main（默认 mixed）， 可以把索引和分支指向远端，同时不动工作区文件——比起重新 clone 一份再装一次依赖，省事得多。
  • 仓库原本用 bun.lock，我这边用 npm 装完会多出一个 package-lock.json。两个锁文件并存没什么害处，但最好别同时提交。
